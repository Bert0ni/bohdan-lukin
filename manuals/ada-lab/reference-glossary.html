Glossary

  • ADA — App Defense Alliance. Industry body (Google-founded; hosted under the Linux Foundation / Joint Development Foundation since 2024) running standardized app-security assessment programs (CASA, MASA, DASA, Cloud Config).
  • CASA — Cloud Application Security Assessment. ADA's web-app/API assessment, derived from OWASP ASVS; required by Google for apps using sensitive/restricted OAuth scopes; annually revalidated.
  • MASA — Mobile Application Security Assessment. ADA's mobile assessment, based on OWASP MASVS/MASTG; supports the Google Play "independent security review" badge.
  • DASA — Developer-Attested Security Assessment. Lighter-touch ADA profile centered on developer attestation validated by a lab. [VERIFY] exact definition.
  • Cloud Config. ADA profile reviewing cloud environment security configuration.
  • Assurance Level (AL1 / AL2). Current CASA levels, both "Lab Tested – Lab Verified." AL1 = evidence verification; AL2 = comprehensive test incl. deployment infra + data storage. The framework user (e.g. Google) sets the required level. (Replaces legacy "Tier 1/2/3".)
  • Tier 1/2/3. Legacy CASA naming still seen on older certificates; mapped to AL0/AL1/AL2.
  • LOV — Letter of Validation. The deliverable an authorized lab issues on a successful assessment (~1-year validity → annual revalidation).
  • Authorized Lab. A lab TrustCB has authorized (per profile) to perform ADA assessments; requires ISO/IEC 17025 + proficiency evaluation.
  • TrustCB. The external certification body ADA uses to manage lab authorization, review profile (proficiency) assessments, and issue the authorization certificate.
  • ISO/IEC 17025. International standard for the competence of testing and calibration laboratories — the gating accreditation for an authorized lab.
  • Accreditation body. The ILAC-MRA-signatory national/regional body that grants ISO/IEC 17025 accreditation (e.g. SNAS, DAkkS, UKAS, A2LA).
  • ILAC MRA. International mutual-recognition arrangement making accreditation internationally recognized.
  • Proficiency / trial evaluation. A TrustCB-overseen supervised assessment proving the lab can correctly execute a profile's methodology before authorization.
  • QMS — Quality Management System. The documented system satisfying ISO/IEC 17025 (impartiality, competence, document/record control, method validation, internal audit, management review).
  • Surveillance. Periodic re-assessment by the accreditation body to maintain accreditation.
  • Impartiality. ISO/IEC 17025 requirement; a lab cannot certify work it built/consulted on.
  • OWASP ASVS. Application Security Verification Standard — the control basis for CASA (v4.0.x historically; v5.0 current OWASP release — [VERIFY] CASA's tracked version).
  • OWASP MASVS / MASTG. Mobile verification standard + testing guide — basis for MASA.
  • Restricted / sensitive OAuth scopes. Google API permissions (e.g. Gmail, Drive) whose use triggers the CASA requirement.
