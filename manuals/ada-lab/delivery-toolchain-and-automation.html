Toolchain & Automation

Automation is the margin and capacity lever (see ../strategy/revenue-model.md): fewer assessor-days per assessment, faster turnaround than manual incumbents, and capacity growth without linear headcount. Build the evidence pipeline early so it doubles as QMS operating records and trial-evaluation rehearsal.

Principles#

  • Evidence-first: every CASA/ASVS requirement maps to a repeatable evidence collector (scan, config pull, or scripted manual check) with a stored, ID'd artifact.
  • Traceable & reproducible: ISO/IEC 17025 demands defensible, repeatable results — automation must log what ran, against what, when, by whom.
  • Modular by standard version: isolate the ASVS/MASVS mapping so a version bump (ASVS 5.0 → next) is a config change, not a rewrite.
  • Human-in-the-loop decisioning: tools gather evidence; authorized assessors decide pass/fail. Never auto-issue a Letter of Validation.

We already operate much of this (web/API, mobile MASTG, cloud offensive/config tooling). The work is integration into a controlled, evidence-producing pipeline, not procurement from zero.

The evidence pipeline (target shape)#

Intake ─▶ Scope & applicability ─▶ Automated collectors (SAST/DAST/SCA/secrets/config)
      ─▶ Normalized evidence store (per-requirement, artifact IDs)
      ─▶ Assessor verification + manual tests (AL2)
      ─▶ Decision records (conform/nonconform + rationale)
      ─▶ QA / independent review
      ─▶ Letter of Validation + retained audit trail

Build vs. buy#

  • Buy/adopt mature scanners (don't reinvent SAST/DAST/SCA).
  • Build the thin orchestration + ASVS-mapping + evidence/decision record layer — that's the proprietary, margin-making, audit-satisfying asset.

Guardrails#

  • Tool output is input to a human decision, never the decision.
  • Keep tool versions and configs under control (ISO/IEC 17025 equipment/method control).
  • Log everything for reproducibility and surveillance audits.
