CASA — Cloud Application Security Assessment

What it is#

CASA is ADA's security assessment for cloud/web applications and APIs. Its most important commercial driver: Google requires CASA for third-party apps that access sensitive or restricted OAuth scopes (e.g. Gmail, Drive, Google Workspace APIs) and for certain marketplace/distribution surfaces. It is revalidated annually, which makes it a recurring compliance spend rather than a one-off.

The standard underneath: OWASP ASVS#

CASA requirements are derived from the OWASP Application Security Verification Standard (ASVS).

  • Historically (Tier 2) CASA aligned to ASVS v4.0.x, with a defined subset of CASA requirements (public materials have cited figures such as ~73 mapped checks for the Tier-2 self-serve set and ~134 for the broader requirement list). [VERIFY] current count.
  • OWASP has since published ASVS 5.0. The ADA notes CASA requirements have been updated. [VERIFY] which ASVS version the current CASA requirements track, and re-map our method when it changes (keep the methodology modular — see ../delivery/casa-methodology.md).

Not every requirement applies to every app; some can be satisfied by pre-existing certifications mapped to CASA (e.g. SOC 2 / ISO 27001 mappings). The developer must pass all applicable CASA requirements.

Assurance levels (current naming)#

ADA's tiering page now describes two levels, both labelled "Lab Tested – Lab Verified":

LevelFormerlyWho testsScope
AL1~Tier 2Authorized lab verifies evidenceLab tested / lab verified against applicable CASA requirements
AL2~Tier 3Authorized lab tests directlyComprehensive — the application plus its deployment infrastructure and user-data storage locations
  • The framework user (e.g. Google) — not the developer — determines the required level, based on data sensitivity, user counts per data type, and risk indicators.
  • A Google Workspace Marketplace badge has been associated with the higher level (AL2). [VERIFY] current badge/level mapping.
  • Legacy "Tier 1/2/3" wording still appears in older certificates and vendor pages; treat AL1/AL2 as current.

The deliverable#

A successful assessment yields a Letter of Validation (LOV) issued by the authorized lab, with roughly one-year validity → the client must re-engage annually. This annuity is central to the revenue model.

Why CASA is our first profile#

  • Largest, most recurring demand of the four profiles (Google OAuth ecosystem is huge).
  • Closest to an existing web/API pentest capability → fastest competency ramp.
  • Clear, standards-based methodology (ASVS) → tractable trial evaluation.
