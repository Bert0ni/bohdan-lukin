ADA Authorized Lab — Operational & Business Plan

Objective. Stand up a new business line: become an App Defense Alliance (ADA) Authorized Lab able to perform and validate assessments across all four ADA security profiles — CASA, MASA, DASA, and Cloud Config — and operate it as a profitable, investable direction for a security company.

Starting position. Greenfield: no ISO/IEC 17025 accreditation yet (the gating prerequisite). This plan therefore carries the full accreditation track in parallel with the ADA/TrustCB authorization track.

⚠️ Accuracy note. Figures for fees, timelines and the exact proficiency-evaluation mechanics are market estimates and must be confirmed with TrustCB and the chosen accreditation body before commitment. Every such item is tagged [VERIFY] in the text. Primary sources are indexed in reference/official-sources.md.

The one-paragraph version#

To sell ADA assessments you must be an Authorized Lab. ADA does not authorize labs itself — it delegates to the certification body TrustCB, which requires every lab to be ISO/IEC 17025-accredited and to pass a proficiency / trial evaluation for each profile it wants to offer. The official path is five steps: (1) petition TrustCB → (2) begin ISO/IEC 17025 accreditation → (3) complete a trial evaluation under TrustCB oversight → (4) complete the ISO/IEC 17025 audit → (5) maintain the authorization (ongoing surveillance). From a standing start the critical path is the ISO/IEC 17025 build-out (~9–18 months [VERIFY]), which can and should run in parallel with building the CASA/MASA delivery capability and the trial evaluations. The commercial thesis: ADA/CASA is a recurring, annually-revalidated, Google-mandated compliance spend with only ~10 global authorized labs — a scarce, defensible, high-retention position that pairs naturally with an existing pentest practice.
